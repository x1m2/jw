## Build and run
### 1. Prerequisites
#### 1.1 **Ubuntu** and **ROS 2**

Use the ROS 2 version configured by this workspace.

#### 1.2. **PCL && Eigen**
PCL    >= 1.8,   Follow [PCL Installation](http://www.pointclouds.org/downloads/linux.html).

Eigen  >= 3.3.4, Follow [Eigen Installation](http://eigen.tuxfamily.org/index.php?title=Main_Page).

#### 1.3. **livox_ros_driver2**

The ROS 2 build depends on `livox_ros_driver2`.

### ROS 2 RoboSense Airy offline localization

`config/reloc_fastlio_airy96.yaml` subscribes to `/rslidar_points` and
`/rslidar_imu_data`. Its `lidar_type: 5` selects the Airy `PointCloud2` input
(`x/y/z/intensity`: float32, `ring`: uint16, `timestamp`: float64 seconds).
The same node performs initial BBS3D relocalization and then continuous
LiDAR-IMU localization.

The map directory must contain the matching `globalmap.pcd` and the BBS3D
`voxelmaps_coords` generated by the map loading workflow. Use a robot parameter
file with the recording sensor's `lidar_to_base.translation` (meters) and
`lidar_to_base.rotation` (`type: rpy_rad` or row-major `matrix`, with `value`); the default shared file
contains the P2 robot calibration.

```bash
ros2 launch fastlio_localization run_launch.py \
  config_file:=reloc_fastlio_airy96.yaml \
  map_path:=/path/to/map \
  robot_param_file:=/path/to/P3_airy96.yaml
ros2 bag play /path/to/airy96_fastlio_20250604_222402 --rate 0.5
```

Check `/reloc_success` for successful relocalization and
`/pose_stamped_localization` for the continuing pose output. The Airy
`extrinsic_T/R` in the profile came from the mapping profile and must match
the sensor that recorded the bag.

## BBS OpenCL 后端

定位节点保持原来的名称、Manager/Worker 控制、重定位成功后的缓存清理、
重力对齐及 NDT/GICP 精配准流程。只替换 BBS 粗定位中的候选搜索/评分后端。

默认 `ENABLE_OPENCL_BBS=ON`，链接由 `src/third_party/3d_bbs/build_opencl.sh`
预先构建并安装的配套 CPU/OpenCL 库；定位包本身不再生成 BBS 库。
CPU 板子先运行 `build_cpu.sh`，然后传 `-DENABLE_OPENCL_BBS=OFF` 编译定位。
默认库安装目录是工作区 `install/bbs3d`，自定义目录使用 `-DBBS3D_ROOT=/安装目录`。
OpenCL 板子需要厂商 GPU 驱动，CPU 构建不依赖 OpenCL。

Airy/MID360s 的定位 YAML 提供：

```yaml
bbs3d_backend: opencl                # cpu / opencl；缺省优先请求 OpenCL
bbs3d_opencl_batch_size: 10000        # 1..65536
bbs3d_opencl_fallback_cpu: true
bbs3d_opencl_verify: false           # 对比验证时逐候选核对 CPU/GPU 评分，额外耗时
```

加载地图时初始化 GPU 地图一次，每轮重定位只更新源点云。GPU 地图的稠密
占据数组仍受库内 128 MiB 上限及设备单次分配限制约束。
初始化、GPU 运行或输入精度条件不满足时，允许回退则使用 CPU 并打印原因；
禁止回退时初始化失败会阻止算法启动，运行阶段失败则本轮 BBS 返回失败。
超时或匹配分数不足按原失败路径处理，不另起一轮 CPU 搜索重置超时。
`bbs3d_timeout_msec` 沿用现有参数；批处理搜索在批次间检查超时，不是硬实时截止。

`[BBS_RUNTIME]` 显示加载时的后端和 GPU 地图大小，`[BBS_SEARCH_STATS]`
显示本轮实际使用的后端、搜索/内核耗时和 GPU 候选数。
只看到 `requested=opencl` 不代表使用了 GPU，需检查 `active` 和 `gpu_candidates`。
保留原 `input_delay`、`pose_delay` 等定位日志，不读取 miao 实验脚本的环境变量，
也不引入点云抓取后退出或离线 bag 回放逻辑。

构建示例（在已加载 ROS 和本工作区依赖的终端）：

```bash
./src/third_party/3d_bbs/build_opencl.sh
colcon build --packages-select fastlio_localization --cmake-args -DENABLE_OPENCL_BBS=ON
```

OTA 更新脚本从 `install/bbs3d/lib/` 复制 BBS 库到 SLAM 的 `lib/`，
并从 `install/bbs3d/bin/` 部署 `voxelmaps_saver`。自定义安装目录使用 `BBS_INSTALL_DIR`。
OpenCL 系统运行库和厂商驱动使用板端现有安装，不从开发机复制。
节点启用 OpenCL 编译后即依赖 OpenCL 动态库；若动态加载器无法加载它，
进程尚未启动，不能使用程序内的 CPU 回退。无 OpenCL 运行库的设备应部署 CPU 构建。
更新脚本仍保留 OTA YAML，需要在实际部署配置中核对上述参数。
地图转换工具部署路径为 `localization/voxelmaps_saver`。

GPU 加速效果和厂商内核正确性需要在目标板使用同一地图和点云复测。
